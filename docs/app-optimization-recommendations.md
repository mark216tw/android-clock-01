# 簡單時鐘 APP 優化建議

> 本文件是歷史規劃與改善建議，可能包含尚未實作或已被目前設計取代的內容；現行功能請以[專案說明](project-overview.md)與[使用指南](user-guide.md)為準。

## 文件目的

本文件依目前程式碼與既有功能，從介面、操作流程、鬧鐘可靠性、無障礙、桌面小工具及產品擴充性提出優化建議。優先級定義如下：

- **P0**：會影響鬧鐘可信度、資料安全或核心功能，應優先處理。
- **P1**：高頻流程或重要無障礙問題，建議下一版完成。
- **P2**：明顯改善使用體驗與產品完整度。
- **P3**：進階功能與長期品質提升。

## 現況摘要

APP 已具備以下優勢：

- 主時鐘支援直向、橫向、全螢幕、12/24 小時、秒數及常亮。
- 提供 16 種數字／指針時鐘樣式、9 種背景紋路、動態開關及多組配色。
- 鬧鐘支援單次／每週重複、名稱、識別色、提前通知、停止與延後。
- 桌面小工具可獨立設定配色、明暗模式、透明背景及字級。
- 使用 Compose、Room、DataStore，程式結構已按 UI、資料與鬧鐘排程分層。

目前最大的產品風險不是視覺選項不足，而是權限或排程失敗時，畫面顯示的狀態可能與實際可否響鈴不一致。對時鐘／鬧鐘類 APP 而言，「可信度」應高於新增樣式或次要功能。

## 介面優化建議

### 1. 主時鐘畫面

#### P1：讓隱藏控制列更容易被理解與操作

目前點擊全畫面切換控制列，控制列並在 4 秒後固定隱藏。首次使用者不一定知道畫面可點擊，TalkBack 或動作較慢的使用者也可能來不及操作。

建議：

- 首次進入顯示一次「點一下顯示控制項」提示，之後不重複干擾。
- 使用 Android `AccessibilityManager` 建議的 timeout；TalkBack 啟用時不自動隱藏。
- 為全畫面點擊區加入「顯示控制項／隱藏控制項」語意。
- 圖示按鈕保留清楚的 `contentDescription`，方向切換時說明切換後的狀態。

相關程式：`ClockScreen.kt`、`SimpleClockApp.kt`。

#### P1：補上時鐘語意

LED、液態玻璃、輝光管及指針樣式主要由 Canvas 或自訂元件繪製，TalkBack 可能無法讀出目前時間。

建議：

- 將時鐘視覺元素合併為單一語意節點。
- 語意內容完整讀出時間、日期與上午／下午，例如「9 月 10 日星期四，上午 8 點 30 分」。
- 秒數可見時不必每秒主動觸發朗讀，避免持續打斷使用者。

相關程式：`ClockScreen.kt`、`ClockDisplays.kt`。

#### P2：提供減少動畫與防烙印模式

動態背景加上常亮適合床頭時鐘，但可能提高耗電、造成暈動，長時間固定顯示也有 OLED 烙印風險。

建議：

- 新增「減少動態效果」，可跟隨系統設定或強制使用靜態背景。
- 新增「防烙印模式」，讓時鐘在不影響閱讀的範圍內定時微幅位移。
- 常亮開啟時提示耗電風險，可提供「插電時才常亮」。
- APP 進入背景時確實暫停無限動畫。

相關程式：`ThemeMotionBackground.kt`、`SettingsScreen.kt`、`SimpleClockApp.kt`。

#### P2：確保彩虹背景文字對比

隨機彩虹背景上的白色文字可能在黃色、淺綠色區域對比不足。

建議採用固定半透明深色底板、文字陰影／描邊，或限制產生的漸層亮度。應以最亮背景區域測試 WCAG 對比，而不是只取平均色。

### 2. 鬧鐘清單

#### P1：顯示「何時會響」而不只顯示設定時間

目前卡片主要顯示時分與重複日，使用者仍需自行判斷是今天、明天或下週。

建議：

- 卡片加入「今天 07:30，還有 2 小時 14 分」或「下週一 07:30」。
- 啟用／編輯成功後顯示 Snackbar：「鬧鐘將在 8 小時 20 分後響鈴」。
- 預設保留使用者手動排序；未來可另提供依下一次響鈴時間排序的檢視模式。
- 權限或排程異常的卡片顯示警告圖示與修復入口，不要偽裝成正常啟用。

相關程式：`AlarmListScreen.kt`、`AlarmTimeCalculator.kt`、`AlarmDao.kt`。

#### P1：識別色只作點綴，不承擔文字可讀性

目前啟用鬧鐘的時間文字直接使用自訂色。黃色等淺色在淺色背景上可能難以閱讀。

建議：

- 時間文字固定使用 `onSurface`，識別色只用於側邊色條、邊框或小型圓點。
- 若識別色必須作為背景，依亮度動態選擇黑／白前景。
- 不以顏色作為唯一狀態提示，額外使用文字或圖示表示啟用、停用、排程異常。

#### P2：刪除改為 Undo

鬧鐘與自訂配色目前可直接刪除，誤觸後無法恢復。

建議刪除後先從畫面移除，顯示 Snackbar「已刪除鬧鐘」及「復原」按鈕，Snackbar 結束後再完成永久刪除。若實作成本需控制，至少先加入確認對話框。

### 3. 鬧鐘編輯器

#### P0：保留原本啟用狀態

目前儲存時固定寫入 `enabled = true`。編輯一個已停用鬧鐘，也會在儲存後重新啟用並觸發權限流程。

建議新建鬧鐘預設啟用，但編輯既有鬧鐘時保留原 `enabled`。啟用行為應由清單 Switch 或編輯器內明確的「啟用此鬧鐘」選項控制。

相關程式：`AlarmListScreen.kt:445-455`。

#### P0：權限拒絕時不要關閉編輯器或遺失輸入

目前按儲存後 UI 立即關閉 Dialog，但真正儲存需等待權限流程。使用者若拒絕權限，輸入內容會消失。

建議：

- 將儲存流程建模為 `Idle / RequestingPermission / Saving / Success / Error`。
- 只有儲存及排程成功後才關閉編輯器。
- 權限被拒時保留所有輸入，提供「前往設定」及「儲存但先停用」。
- 使用 `SavedStateHandle` 或可保存狀態，避免系統設定頁期間程序被回收後遺失草稿。

相關程式：`AlarmListScreen.kt:150-180`、`SimpleClockApp.kt:109-121`、`MainActivity.kt:88-138`。

#### P1：改善色彩與星期選擇的無障礙

建議：

- 色點觸控範圍由 36dp 提升至至少 48dp。
- 六個預設色提供色名與選取狀態，Hue 滑桿同步顯示目前 HEX 與色相。
- 星期 Chip 的語意使用完整名稱「星期一」至「星期日」，畫面仍可顯示短名稱。
- 自訂顏色按鈕顯示當前 HEX，並驗證所有前景／背景組合的對比。

相關程式：`AlarmListScreen.kt:274-425`。

#### P2：將長表單改為全螢幕編輯頁或自適應 Sheet

TimePicker、名稱、星期、20 個色點及自訂調色集中在巢狀 Dialog，手機橫向或大字體模式下操作負擔高。

建議：

- 手機使用全螢幕編輯頁，大螢幕使用寬版 Dialog。
- 固定頂部標題與底部取消／儲存操作，中間內容獨立捲動。
- 預設色收合成一列最近使用色，完整色盤以次級頁面開啟。
- 避免 Dialog 內再開 Dialog。

### 4. 響鈴畫面

#### P0：確保停止與延後的操作結果可信

目前畫面送出停止／延後 action 後便關閉；若 Service 未收到 action 或延後排程失敗，使用者可能失去控制畫面但聲音仍持續，或誤以為已延後。

建議：

- Service 回報成功後才關閉 Activity。
- 操作期間顯示短暫 loading 並防止連點。
- 延後失敗時保留畫面，顯示錯誤並允許重試或停止。
- 停止按鈕文字顏色需依鬧鐘識別色動態選擇，確保對比。

相關程式：`AlarmActivity.kt`、`AlarmRingingService.kt`。

#### P2：降低睡醒時的操作負擔

建議將「停止」與「延後」維持大尺寸且位置穩定，避免兩個按鈕顏色過於接近；可考慮停止需滑動確認，但不建議加入複雜解題機制為預設行為。

### 5. 設定畫面

#### P2：重新整理資訊架構

設定項目多，建議分為「顯示」、「外觀」、「動態與常亮」、「時鐘樣式」四個區段，並讓目前值直接顯示於列項副標題。高頻設定在前，實驗性或高耗電選項在後。

#### P2：簡化隨機彩虹操作

目前選取卡片、重新產生與儲存配色的意圖容易混淆。

建議：

- 點卡片只負責選取，不同時重新產生。
- 使用明確的「重新產生」按鈕改變預覽。
- 未儲存的新配色顯示狀態提示。
- 覆蓋目前預覽時可復原上一組配色。

#### P2：提供還原預設值

加入「還原顯示設定」與「還原全部設定」，並在執行前列出影響範圍。鬧鐘資料不應包含在一般設定重設中。

### 6. 桌面小工具

#### P2：限制不合理字級並強化預覽

目前字級只要求大於零，極大數值可能造成截字或 RemoteViews 版面異常。

建議：

- 提供建議範圍及合理軟上限，超出時顯示警告。
- 預覽應使用與實際 widget 相同的寬高與截字規則。
- 依 widget 寬度提供小、中、大三種資訊層級。

#### P2：改善透明背景可讀性

透明背景無法預測桌布顏色。建議提供文字陰影／描邊、半透明底色強度，或在設定頁明確提醒對比風險。

## 功能與可靠性優化建議

### 1. 鬧鐘狀態與系統能力分離（P0）

目前 APP 啟動時若通知、精準鬧鐘或全螢幕能力不足，可能將所有已啟用鬧鐘永久寫為停用。暫時缺少權限不等於使用者取消鬧鐘，不應改寫其意圖。

建議資料概念至少分為：

- `enabled`：使用者是否希望此鬧鐘啟用。
- `scheduleStatus`：已排程、等待權限、排程失敗或不適用。
- `scheduleError`：供 UI 說明與修復使用，可不必永久存入資料庫。

權限恢復、裝置重啟、時間或時區變更後，應重新嘗試排程，而不是要求使用者逐一重新啟用。

相關程式：`MainActivity.kt:58-73`、`MainViewModel.kt:128-136`。

### 2. 將權限拆成必要與可降級能力（P0）

精準排程、通知及全螢幕顯示不是完全相同的能力。尤其無法使用全螢幕 Intent 時，仍應盡可能以高重要性通知與聲音響鈴，而不是直接禁止啟用。

建議：

- 明確列出每項能力目前狀態及用途。
- 精準鬧鐘不可用時，說明系統限制並提供設定入口。
- 全螢幕不可用時降級為 heads-up／高重要性通知，不永久停用鬧鐘。
- 通知 channel 被關閉時提供直接修復入口。
- 權限流程中斷時保留待儲存資料。

### 3. 排程結果必須回到 UI（P0）

目前 `saveAlarm()` 忽略 `schedule()` 回傳值，可能出現資料顯示已啟用但實際沒有排程。

建議 Repository 或 ViewModel 回傳明確結果：

- `Scheduled(nextTriggerAt)`
- `SavedDisabled`
- `PermissionRequired(capability)`
- `ScheduleFailed(reason)`

UI 只有在 `Scheduled` 或 `SavedDisabled` 時顯示成功，其他狀態需顯示可採取的修復動作。

### 4. 響鈴前驗證鬧鐘仍有效（P0）

Receiver 應先查詢 Room，確認鬧鐘存在、啟用且本次觸發仍有效，再啟動響鈴 Service。這可避免刪除、停用後殘留的 PendingIntent 誤響。

相關程式：`AlarmReceiver.kt`。

### 5. 定義多鬧鐘同時觸發策略（P0）

目前響鈴 Service 使用單一全域狀態，短時間觸發第二個鬧鐘時可能覆寫第一個 alarm ID，停止或延後也可能作用於錯誤鬧鐘。

建議先定義產品規則：同時觸發時合併成一個響鈴工作階段，畫面列出所有到期鬧鐘；或將後到鬧鐘排隊。所有 notification ID、PendingIntent request code 與 action 都需包含 alarm ID 或 session ID。

### 6. 明確定義資料庫升級策略（P0）

目前開發版本明確不保證鬧鐘資料向下相容。schema 變更時提升 Room 版本並允許 destructive migration，同時在 README 告知使用者；DataStore 顯示設定維持獨立，不隨資料庫重建而清除。正式版若改為保留資料，再啟用 schema export 並補上 migration test。

相關程式：`AppDatabase.kt`。

### 7. 增加個人化鬧鐘能力（P3）

在可靠性完成後，可依序加入：

- 每個鬧鐘自訂鈴聲。
- 震動開關與震動模式。
- 音量漸強及漸強時間。
- 自訂延後分鐘數與最多延後次數。
- 單次略過重複鬧鐘，而不是永久停用。
- 下一個假日略過；需注意地區資料與產品複雜度，應列為選配。

不建議短期內同時加入世界時鐘、碼表與計時器，除非產品定位要從「大字時鐘＋鬧鐘」擴張為完整 Clock Suite。先把核心鬧鐘做到可信，比擴大功能面更重要。

### 8. 備份與匯出（P3）

可提供 JSON 匯出／匯入，內容包含鬧鐘與顯示設定，但不包含系統權限。匯入時需驗證版本、時間範圍與顏色格式，並讓使用者選擇合併或覆蓋。

## 品質與測試建議

### P0 測試

- 權限拒絕後，鬧鐘資料與編輯草稿不遺失。
- 權限恢復後，原先啟用的鬧鐘可自動重新排程。
- 排程失敗時 UI 不顯示為正常啟用。
- 已刪除或已停用鬧鐘的殘留 Intent 不會啟動響鈴。
- 同分鐘兩個鬧鐘的停止與延後不會控制錯誤項目。
- 不相容 schema 可乾淨重建資料庫，且不影響 DataStore 顯示設定。

### P1 測試

- 夏令時間開始／結束、手動改時區、手動改時間及重開機。
- 通知權限、通知 channel、精準鬧鐘及全螢幕權限的所有組合。
- Compose UI 在 TalkBack、200% 字體、直向、橫向及小螢幕下可操作。
- 所有自訂色、淺色／深色及彩虹主題符合文字對比要求。
- Widget 在不同寬度、字級與 Launcher 下不截斷核心時間資訊。

## 建議版本切分

### v1.3.x：核心修正

- 修正編輯停用鬧鐘後被自動啟用。
- 權限不足不再永久停用鬧鐘。
- 排程結果回饋 UI。
- 響鈴前驗證資料。
- 文件化 destructive migration 策略並驗證重建流程。

### v1.4：可信度與無障礙

- 顯示下一次響鈴與倒數。
- 權限狀態卡與修復入口。
- TalkBack 時間語意、48dp 觸控目標、星期完整語意。
- 色彩與響鈴按鈕對比修正。
- 多鬧鐘同時觸發策略。

### v1.5：體驗完善

- 全螢幕／自適應鬧鐘編輯器。
- 刪除 Undo。
- 減少動畫、防烙印及插電常亮。
- Widget 自適應資訊層級與透明背景可讀性。

### 後續版本

- 自訂鈴聲、震動、音量漸強及延後規則。
- 設定與鬧鐘匯出／匯入。
- 是否擴充計時器、碼表及世界時鐘，另行進行產品驗證。
