# 簡單時鐘 APP 優化待辦事項

> 本文件是歷史規劃清單，完成狀態不代表正式版本承諾；現行功能請以[專案說明](project-overview.md)與[使用指南](user-guide.md)為準。

## 使用方式

- 勾選格式：`[ ]` 未開始、`[x]` 已完成。
- 唯一編號：每條可勾選事項使用 `OPT-###`，供 Issue、commit 與討論交叉引用。
- 建議依 P0、P1、P2、P3 順序執行。
- 每項完成定義包含程式、測試與使用者可見結果，不應只以程式可編譯作為完成標準。
- 詳細背景與理由請參考 [APP 優化建議](app-optimization-recommendations.md)。

## P0：核心可信度與資料安全

### T01 保留鬧鐘原本的啟用狀態

- [x] `OPT-001` 新建鬧鐘可預設 `enabled = true`。
- [x] `OPT-002` 編輯既有鬧鐘時，不再固定寫入 `enabled = true`。
- [x] `OPT-003` 編輯停用鬧鐘的名稱、時間、星期或顏色後，仍維持停用。
- [ ] `OPT-004` 新增 ViewModel 或 UI 單元測試覆蓋啟用與停用兩種編輯情境。

驗收條件：編輯已停用鬧鐘並儲存，不觸發權限要求、不進行排程，清單 Switch 仍為關閉。

相關檔案：`AlarmListScreen.kt`。

- [x] `OPT-006` 儲存流程回傳停用儲存、排程成功、需要權限與排程失敗等結果。
- [x] `OPT-007` 只有儲存／排程成功後才關閉編輯器。

- [ ] `OPT-009` 提供「前往設定」與「儲存但先停用」操作。
- [x] `OPT-010` 儲存成功後顯示下一次響鈴時間。
- [x] `OPT-011` 排程失敗時顯示可理解且可重試的錯誤訊息。

驗收條件：拒絕任何權限後返回 APP，編輯器內容仍存在；畫面不會把未排程成功的鬧鐘顯示為正常啟用。

相依：T01。

### T03 分離使用者啟用意圖與排程狀態
